🔑 Keys in DBMS

Learn about different types of keys used in DBMS.

📖 What is a Key?

A key is an attribute or a set of attributes used to identify a record uniquely in a table.

Simple Meaning: A key helps us to identify a particular record in a table.

🔐 1. Primary Key

A Primary Key uniquely identifies each record in a table. It cannot contain duplicate or NULL values.

Example:

In a Student table, Student_ID can be used as a Primary Key.

Simple Meaning: Primary Key gives a unique identity to each record.

🔗 2. Foreign Key

A Foreign Key is an attribute that connects one table with another table.

Example:

Student_ID in the Student table can be connected to Student_ID in another related table.

Simple Meaning: Foreign Key creates a connection between two tables.

⭐ 3. Candidate Key

A Candidate Key is an attribute that can uniquely identify each record in a table.

Example:

Student_ID and Email_ID may both uniquely identify a student. Both can be Candidate Keys.

Simple Meaning: Candidate Keys are possible choices for the Primary Key.

🔑 4. Super Key

A Super Key is a set of one or more attributes that can uniquely identify a record.

Example:

Student_ID alone can identify a student. Student_ID + Name can also identify the student.

Simple Meaning: Super Key is any combination of attributes that uniquely identifies a record.

🔄 5. Alternate Key

An Alternate Key is a Candidate Key that is not selected as the Primary Key.

Example:

If Student_ID is selected as the Primary Key and Email_ID is another Candidate Key, then Email_ID becomes an Alternate Key.

Simple Meaning: Alternate Key is a Candidate Key that is not used as the Primary Key.

🧩 6. Composite Key

A Composite Key is made using two or more attributes together to uniquely identify a record.

Example:

Student_ID + Course_ID together can uniquely identify a student's course record.

Simple Meaning: Two or more attributes together form a Composite Key.

📊 Summary of Keys

  • Primary Key: Uniquely identifies each record.
  • Foreign Key: Connects two tables.
  • Candidate Key: Possible Primary Key.
  • Super Key: Uniquely identifies a record using one or more attributes.
  • Alternate Key: Candidate Key not selected as Primary Key.
  • Composite Key: Combination of two or more attributes.
