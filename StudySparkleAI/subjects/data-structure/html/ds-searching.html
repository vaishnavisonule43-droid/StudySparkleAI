01 • BASIC CONCEPT

What is Searching?

Searching is one of the basic operations in Data Structures. It is used to find whether a particular element exists in a collection of data and, if it exists, to determine its location.

DEFINITION

Searching is the process of finding the location of a required element, called the key, in a collection of data.

Simple Example

Suppose the array contains these values. We want to find the key 30.

Index 010
Index 120
Index 230FOUND
Index 340
Index 450

The required value 30 is present at index 2, which is position 3. Remember that an array index usually starts at 0, but a position starts at 1.

Key

The value we want to find. Example: 30.

Index

The zero-based location of an element. Example: 2.

Result

The location of the key, or a message that it was not found.

02 • WHY SEARCHING?

Need and Applications of Searching

Searching helps us retrieve the required information from a large collection of records without checking every record manually.

Finding a customer account using an account number or customer ID.

🛒

03 • MAIN TYPES

Types of Searching

➡️

1. Linear Search

Checks elements one by one from the beginning until the key is found or the list ends.

  • Works with sorted and unsorted data.
  • Simple to implement.
  • Worst-case time: O(n).
Learn Linear Search ↓
✂️

2. Binary Search

Checks the middle element and eliminates half of the remaining search range at each step.

  • Requires sorted data.
  • Efficient for large sorted arrays.
  • Worst-case time: O(log n).
Learn Binary Search ↓
Important: Binary Search should not be applied directly to an unsorted array. The sorted order is what allows it to discard half of the search range safely.
04 • METHOD ONE

Linear Search

DEFINITION

Linear Search is a searching technique that compares the key with each element one by one, starting from the first element until the key is found or all elements have been checked.

Working of Linear Search

  1. Start from the first element of the array.
  2. Compare the current element with the key.
  3. If both are equal, return the element's index.
  4. If they are not equal, move to the next element.
  5. Repeat until the key is found or the array ends.
  6. If the key is not present, return -1.

Example

Array: 12, 25, 18, 40, 35; Key: 40

Step Element Checked Comparison Result
1 12 12 == 40? No
2 25 25 == 40? No
3 18 18 == 40? No
4 40 40 == 40? Yes — Found!
Result: Key 40 is found at index 3, which is position 4. Total comparisons = 4.

Advantages

  • Easy to understand and implement.
  • Works with both sorted and unsorted arrays.
  • Does not require additional sorting.

Disadvantages

  • May check every element when the key is near the end or absent.
  • Can be inefficient for very large collections.

06 • METHOD TWO

Binary Search

DEFINITION

Binary Search is a searching technique that finds a key in sorted data by repeatedly checking the middle element and reducing the search range to one half.

Important Terms

LOW

The index of the first element in the current search range.

HIGH

The index of the last element in the current search range.

MID

The index of the middle element, calculated using (LOW + HIGH) / 2 with integer division.

KEY

The value we want to find in the sorted array.

Working of Binary Search

  1. Set LOW = 0 and HIGH = n - 1.
  2. Calculate MID = LOW + (HIGH - LOW) / 2 using integer division.
  3. If A[MID] == KEY, the key is found.
  4. If KEY < A[MID], search the left half by setting HIGH = MID - 1.
  5. If KEY > A[MID], search the right half by setting LOW = MID + 1.
  6. Repeat while LOW <= HIGH. If LOW > HIGH, the key is not present.
Exam tip: If KEY is smaller than MID's element, move HIGH left. If KEY is greater than MID's element, move LOW right. Do not reverse these rules.

Why is Binary Search faster?

After each unsuccessful comparison, Binary Search eliminates approximately half of the remaining candidates. Linear Search usually eliminates only one candidate per comparison.

07 • SOLVED EXAMPLE

Binary Search: Step-by-Step Dry Run

Question: Find key 40 in the sorted array [10, 20, 30, 40, 50, 60, 70].

Step LOW HIGH MID A[MID] Action
1 0 6 3 40 Found!

Calculation:

LOW = 0
HIGH = 6
MID = (LOW + HIGH) / 2
MID = (0 + 6) / 2 = 3

A[3] = 40
KEY = 40

KEY == A[MID]
Therefore, the key is found at index 3.
Position = 3 + 1 = 4.

Example requiring multiple steps

Find 60 in [10, 20, 30, 40, 50, 60, 70].

Step LOW HIGH MID A[MID] Decision
1 0 6 3 40 60 > 40, set LOW = 4
2 4 6 5 60 Found at index 5
Final answer: Key 60 is found at index 5 (position 6) after 2 comparisons.

09 • ALGORITHM & PROGRAM

Algorithms and C Programs

Linear Search Algorithm

1. Start
2. Read n, array A and key
3. For i = 0 to n - 1
4.     If A[i] == key, print index i and stop
5. If key is not found, print "Not found"
6. Stop

Linear Search in C

#include <stdio.h>

int main() {
    int a[100], n, key, i, found = 0;

    printf("Enter number of elements: ");
    scanf("%d", &n);

    if (n < 1 || n > 100) {
        printf("Invalid size");
        return 0;
    }

    printf("Enter array elements: ");
    for (i = 0; i < n; i++)
        scanf("%d", &a[i]);

    printf("Enter key to search: ");
    scanf("%d", &key);

    for (i = 0; i < n; i++) {
        if (a[i] == key) {
            printf("Found at position %d", i + 1);
            found = 1;
            break;
        }
    }

    if (!found)
        printf("Element not found");

    return 0;
}

Binary Search Algorithm

1. Start
2. Read sorted array A and key
3. Set LOW = 0 and HIGH = n - 1
4. While LOW <= HIGH
5.     MID = LOW + (HIGH - LOW) / 2
6.     If A[MID] == key, return MID
7.     If key < A[MID], set HIGH = MID - 1
8.     Otherwise, set LOW = MID + 1
9. If not found, return -1
10. Stop

Binary Search in C

#include <stdio.h>

int main() {
    int a[100], n, key, low, high, mid, i;

    printf("Enter number of elements: ");
    scanf("%d", &n);

    if (n < 1 || n > 100) {
        printf("Invalid size");
        return 0;
    }

    printf("Enter sorted array elements: ");
    for (i = 0; i < n; i++)
        scanf("%d", &a[i]);

    printf("Enter key to search: ");
    scanf("%d", &key);

    low = 0;
    high = n - 1;

    while (low <= high) {
        mid = low + (high - low) / 2;

        if (a[mid] == key) {
            printf("Found at position %d", mid + 1);
            return 0;
        } else if (key < a[mid]) {
            high = mid - 1;
        } else {
            low = mid + 1;
        }
    }

    printf("Element not found");
    return 0;
}
The Binary Search C program expects the input array to be sorted in ascending order. Entering an unsorted array can produce an incorrect result.
10 • PERFORMANCE

Time and Space Complexity

LINEAR SEARCH • WORST CASE O(n)

May check all n elements.

BINARY SEARCH • WORST CASE O(log n)

Repeatedly halves the search range.

Complexity Table

Algorithm Best Case Average Case Worst Case Extra Space
Linear Search O(1) O(n) O(n) O(1)
Binary Search (iterative) O(1) O(log n) O(log n) O(1)

What does this mean?

O(1): Constant time — the operation takes a fixed amount of work, independent of the input size.

O(n): Linear time — the amount of work can grow proportionally to the number of elements.

O(log n): Logarithmic time — the search range is repeatedly divided, so the number of steps grows slowly as n increases.

For an array of 1,024 elements, Binary Search needs at most about 11 comparisons in the worst case, whereas Linear Search may need 1,024. The exact number depends on the search and array size.
11 • IMPORTANT DIFFERENCES

Linear Search vs Binary Search

Feature Linear Search Binary Search
Method Checks elements one by one. Checks the middle and halves the range.
Data requirement Sorted or unsorted. Must be sorted.
Best case O(1) O(1)
Worst-case time O(n) O(log n)
Implementation Very simple. Requires LOW, HIGH and MID.
Best suited for Small or unsorted collections. Large sorted arrays.
12 • QUICK EVALUATION

Advantages and Disadvantages

Linear Search

Advantages

  • Simple to write and understand.
  • Works on unsorted data.
  • No sorting is required first.

Disadvantages

  • May require many comparisons.
  • Slow for large collections in the worst case.

Binary Search

Advantages

  • Fast for large sorted arrays.
  • Requires fewer comparisons.
  • Iterative version uses O(1) extra space.

Disadvantages

  • Requires sorted data.
  • Its logic is more complex than Linear Search.
  • Sorting first may add extra cost if the data is not already sorted.

14 • PRACTICE

Important Exam Questions

1. What is Searching?

Searching is the process of finding the location of a required element, called the key, in a collection of data.

2. Explain Linear Search with an example.

Linear Search compares the key with each element one by one until the key is found or the array ends. For example, searching 30 in [10, 20, 30] checks 10, then 20, then finds 30 at index 2.

3. Explain Binary Search with an example.

Binary Search works on sorted data. It compares the key with the middle element and repeatedly selects the left or right half until the key is found or the range becomes empty.

4. Differentiate between Linear and Binary Search.

Linear Search checks elements one by one and works on unsorted data, with worst-case time O(n). Binary Search repeatedly halves the search range, requires sorted data and has worst-case time O(log n).

5. What are LOW, HIGH and MID?

LOW is the first index of the current search range, HIGH is the last index, and MID is the middle index calculated using integer division.

6. Write the time complexity of both searching methods.

Linear Search: best O(1), average O(n), worst O(n). Iterative Binary Search: best O(1), average O(log n), worst O(log n).

7. Why does Binary Search require sorted data?

Sorted order tells us which half may contain the key. Without sorted order, discarding half of the array may discard the required element.

8. Find 25 using Linear Search in [5, 15, 25, 35, 45].

Compare 5 with 25, then 15 with 25, then 25 with 25. The key is found at index 2 (position 3) after 3 comparisons.

9. What happens if Binary Search does not find the key?

The search range eventually becomes empty, meaning LOW is greater than HIGH. The algorithm returns −1 or displays “Element not found.”
