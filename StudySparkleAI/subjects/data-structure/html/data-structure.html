THE FOUNDATION

What is a Data Structure?

A data structure is a method of organizing and storing data in a computer so that it can be accessed, updated, searched and processed efficiently.

Different structures are suited to different tasks. For example, arrays provide indexed access, stacks follow LIFO order, queues follow FIFO order, and trees represent hierarchical relationships.

✦

Remember: The right data structure can make a program easier to understand and more efficient.

FUNDAMENTALS

Introduction to Data Structures

Data structures organize data so operations can be performed in a useful and efficient way. Common operations include traversal, searching, insertion, deletion and updating.

  • Linear: Arrays, linked lists, stacks and queues.
  • Non-linear: Trees and graphs.
  • Selection: Choose a structure based on the operations and requirements of the problem.
Study tip: Learn each structure's layout, operations, advantages and limitations.
All topics ↑
02
LINEAR STRUCTURE

Arrays

An array stores elements in indexed positions. In many languages, array elements have the same declared type and occupy a contiguous memory region.

  • Access: Index-based access is typically O(1).
  • Traversal: Visiting every element takes O(n) time.
  • Insertion/deletion: May require shifting elements, often O(n).
Example: [10, 20, 30, 40] stores four values at indexes 0 through 3 in a zero-indexed language.
All topics ↑
03
LINEAR STRUCTURE

Linked List

A linked list is made of nodes. Each node stores data and one or more links to other nodes.

  • Singly linked: Each node links to the next node.
  • Doubly linked: Each node can link forward and backward.
  • Circular linked: The final node links back to a node at the start, often the head.
Remember: Direct access by index is not usually O(1); reaching a particular node often requires traversal.
All topics ↑
04
LINEAR STRUCTURE

Stack

A stack follows LIFO — Last In, First Out. The most recently added item is the first one removed.

  • Push: Add an item to the top.
  • Pop: Remove the top item.
  • Peek/Top: Inspect the top item without removing it.
Applications: Function-call management, undo operations, expression evaluation and backtracking.
All topics ↑
05
LINEAR STRUCTURE

Queue

A standard queue follows FIFO — First In, First Out. Items are added at the rear and removed from the front.

  • Enqueue: Add an item.
  • Dequeue: Remove an item.
  • Variants: Circular queue, deque and priority queue.
Applications: Task scheduling, print queues and processing requests in order.
All topics ↑
06
NON-LINEAR STRUCTURE

Trees

A tree represents hierarchical relationships through nodes and edges. A rooted tree has a root node, and nodes can have children.

  • Root: The top node of a rooted tree.
  • Leaf: A node with no children.
  • Traversals: Preorder, inorder and postorder are common binary-tree traversals; level-order uses levels.
Applications: File systems, hierarchical data and search structures.
All topics ↑
07
NON-LINEAR STRUCTURE

Heap

A binary heap is a complete binary tree that follows a heap property. It is commonly implemented using an array.

  • Min-heap: Each parent is less than or equal to its children.
  • Max-heap: Each parent is greater than or equal to its children.
  • Typical operations: Read the root in O(1), insert in O(log n), and remove the root in O(log n).
Applications: Priority queues and heap sort.
All topics ↑
08
SPECIALIZED STRUCTURE

Priority Queue

A priority queue removes the element with the highest or lowest priority according to its defined ordering. It does not necessarily follow arrival order.

  • Insert: Add an element with a priority.
  • Peek: Inspect the next element to be served.
  • Remove: Extract the element with the next priority.
Applications: Scheduling, shortest-path algorithms and event simulation. A heap is a common implementation.
All topics ↑
09
ALGORITHMS

Searching

Searching finds whether a target value exists in a collection and, when appropriate, returns its location.

  • Linear search: Checks elements one by one; worst-case time O(n).
  • Binary search: Repeatedly halves a sorted search range; time O(log n).
  • Requirement: Binary search generally requires sorted data and efficient access to the middle element.
Exam point: State the input condition as well as the time complexity when comparing algorithms.
All topics ↑
10
ALGORITHMS

Sorting

Sorting arranges data according to a chosen order, such as ascending or descending.

  • Bubble sort: Repeatedly compares and swaps adjacent elements.
  • Selection sort: Selects the next smallest or largest element for its position.
  • Insertion sort: Inserts each new element into a sorted portion.
  • Merge sort: Divides data and merges sorted parts; typically O(n log n).
  • Quick sort: Partitions around a pivot; average time O(n log n), worst case O(n²) in common implementations.
Remember: Compare time complexity, extra memory, stability and the nature of the input.
All topics ↑

DATA ACCESS

Hashing

Hashing uses a hash function to map a key to an index or bucket in a hash table.

  • Hash function: Computes a location from a key.
  • Collision: Occurs when different keys map to the same bucket.
  • Collision handling: Separate chaining and open addressing are common methods.
Performance: Hash tables can provide average-case O(1) lookup under suitable conditions, but worst-case lookup can be O(n).
All topics ↑

PROBLEM SOLVING

Recursion

Recursion occurs when a function solves a problem by calling itself on a smaller or simpler version of that problem.

  • Base case: Stops further recursive calls.
  • Recursive case: Reduces the problem and calls the function again.
  • Call stack: Tracks active function calls and their local state.
Important: Without a reachable base case, recursion may continue until a runtime limit is reached.
All topics ↑

NON-LINEAR STRUCTURE

Graph

A graph consists of vertices (nodes) and edges (connections). Graphs can model relationships and routes between entities.

  • Directed graph: Edges have direction.
  • Undirected graph: Edges represent two-way connections.
  • Representations: Adjacency lists and adjacency matrices.
  • Traversal: Breadth-first search (BFS) and depth-first search (DFS).
Applications: Maps, computer networks, dependency systems and social connections.
All topics ↑

ANALYSIS & TECHNIQUES

Time & Space Complexity

Complexity describes how an algorithm's resource requirements grow as input size increases. Big O is commonly used to express an upper-bound growth rate.

  • O(1): Constant growth.
  • O(log n): Logarithmic growth.
  • O(n): Linear growth.
  • O(n log n): Common in efficient comparison sorting.
  • O(n²): Often seen in algorithms with nested passes over input.
Remember: Time complexity concerns running-time growth; space complexity concerns memory usage growth. Actual performance also depends on implementation and hardware.
