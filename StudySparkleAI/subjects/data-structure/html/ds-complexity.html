⏱️ Complexity in Data Structure

Learn the basic concepts of Time and Space Complexity.

What is Complexity?

Complexity is used to measure how much time and memory an algorithm requires to solve a problem.

Definition: Complexity is the measurement of the resources required by an algorithm to solve a problem.

Types of Complexity

There are mainly two types of complexity in Data Structure:

  • Time Complexity
  • Space Complexity

1. Time Complexity

Time Complexity measures the amount of time an algorithm takes to complete its execution as the input size increases.

Definition: Time Complexity is the amount of time required by an algorithm to execute for a given input size.

Example

If an algorithm checks every element of an array one by one, the time required increases when the number of elements increases.

2. Space Complexity

Space Complexity measures the amount of memory required by an algorithm during its execution.

Definition: Space Complexity is the amount of memory required by an algorithm to solve a problem.

Example

If an algorithm creates an additional array to store data, the memory used by that array is considered in space complexity.

Big O Notation

Big O notation is used to describe the performance of an algorithm as the input size increases.

Definition: Big O notation represents the upper bound or worst-case growth rate of an algorithm.

Common Time Complexities

1. O(1) - Constant Time

The algorithm takes almost the same amount of time regardless of the input size.

Example: Accessing an element of an array using its index.

2. O(n) - Linear Time

The execution time increases directly with the input size.

Example: Searching an element using Linear Search.

3. O(n²) - Quadratic Time

The execution time increases approximately with the square of the input size.

Example: Bubble Sort in the worst case.

4. O(log n) - Logarithmic Time

The algorithm reduces the problem size step by step. It is generally faster than linear time for large inputs.

Example: Binary Search.

Complexity Comparison

  • O(1) → Very Fast
  • O(log n) → Fast
  • O(n) → Linear
  • O(n²) → Slower for large input
Simple Order:
O(1) → O(log n) → O(n) → O(n²)

Best, Average and Worst Case

1. Best Case

Best Case represents the minimum time required by an algorithm for a particular input.

2. Average Case

Average Case represents the expected time required for normal or average inputs.

3. Worst Case

Worst Case represents the maximum time required by an algorithm for a particular input.

Importance of Complexity

  • Helps compare different algorithms.
  • Helps select an efficient algorithm.
  • Helps reduce execution time.
  • Helps reduce memory usage.
  • Useful when working with large amounts of data.

Simple Example

Suppose an array contains 100 elements. If we check every element one by one, the algorithm may need to check many elements. Therefore, its time complexity is O(n).

Simple Example:
Input increases → Work increases → Time Complexity increases

Conclusion

Complexity helps us understand the time and memory required by an algorithm. Time Complexity and Space Complexity are important for designing efficient algorithms.
