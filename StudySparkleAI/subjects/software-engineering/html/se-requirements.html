Software Engineering Notes

📌 What are Software Requirements?

Software requirements describe what a software system should do and what features it should provide. They define the needs and expectations of users from the software.

In simple words, requirements tell developers what the software should do and how the software should work.

⚙️ Requirement Engineering

Requirement Engineering is the systematic process of collecting, analyzing, documenting and managing software requirements.

⚙️ Functional Requirements

Functional requirements describe the functions and operations that the software must perform.

  • User registration
  • User login
  • Search facility
  • Adding and deleting records
  • Report generation
  • Payment processing
💡 Example: In a college website, students should be able to login and view their marks.

⭐ Non-Functional Requirements

Non-functional requirements describe the quality, performance and other characteristics of the system.

  • 🔐 Security
  • ⚡ Performance
  • 🛡️ Reliability
  • 😊 Usability
  • 📈 Scalability
  • 🔧 Maintainability
💡 Example: A website should load within a few seconds and protect user information.

📝 Requirement Gathering Techniques

Developers use different techniques to understand what users need from the software.

  1. Interview: Talking directly with users or customers.
  2. Questionnaire: Collecting information through questions.
  3. Observation: Watching how users perform their work.
  4. Discussion: Discussing requirements with stakeholders.
  5. Document Analysis: Studying existing documents and systems.

📄 SRS - Software Requirements Specification

SRS stands for Software Requirements Specification. It is a document that describes all the requirements of a software system.

Important contents of SRS:

  • Introduction
  • Overall description
  • Functional requirements
  • Non-functional requirements
  • System constraints
  • External interfaces

✅ Importance of Software Requirements

  • Helps understand customer needs.
  • Reduces misunderstanding.
  • Helps developers plan the project.
  • Reduces development cost and time.
  • Provides a base for testing.
  • Improves software quality.

💡 Real-Life Example

Suppose we are developing a College Management System.

👨‍🎓 Student Login
📚 View Subjects
📝 View Marks
💰 Fee Payment
📄 Download Result
🔐 Secure Student Data

These needs become the requirements of the College Management System.

🎯 Quick Summary

Requirements explain what the software should do. Functional requirements describe the functions, while non-functional requirements describe quality and performance. SRS documents all these requirements.
