💧 Waterfall Model

Software Engineering Notes

📖 What is Waterfall Model?

The Waterfall Model is a linear and sequential software development model.

In this model, software development is completed step-by-step. One phase must be completed before moving to the next phase.

Simple Definition: Waterfall Model is a software development model where each phase is completed one after another in a fixed sequence.

💧 Waterfall Model Process

Each phase flows down to the next phase.

1

Requirement Analysis

Collect and understand requirements.

↓
2

System Design

Design the structure of the software.

↓
3

Implementation

Write the actual program code.

↓
4

Testing

Find and fix errors and bugs.

↓
5

Deployment

Deliver the software to users.

↓
6

Maintenance

Update and maintain the software.

📚 Phases of Waterfall Model

  1. Requirement Analysis
  2. System Design
  3. Implementation
  4. Testing
  5. Deployment
  6. Maintenance

1️⃣ Requirement Analysis

All requirements of the customer are collected and documented.

Developers understand what the software should do.

2️⃣ System Design

The complete design of the software is prepared.

Database, user interface, system architecture and other components are planned.

3️⃣ Implementation

Developers start writing the actual program code.

The design is converted into a working software system.

4️⃣ Testing

The software is tested to find bugs and errors.

Developers fix the errors found during testing.

5️⃣ Deployment

After successful testing, the completed software is delivered or released to users.

6️⃣ Maintenance

After deployment, the software is maintained, updated and improved whenever necessary.

✅ Advantages of Waterfall Model

  • Simple and easy to understand.
  • Easy to manage because phases are fixed.
  • Each phase has clear documentation.
  • Easy to track project progress.
  • Works well when requirements are clear.

❌ Disadvantages of Waterfall Model

  • Difficult to make changes after a phase is completed.
  • Testing happens relatively late in the process.
  • Not suitable when requirements change frequently.
  • Working software is available only after major development stages.
  • Customer feedback comes late.

🎯 When is Waterfall Model Used?

  • When requirements are clear and fixed.
  • When technology is well understood.
  • When the project is small and predictable.
  • When detailed documentation is important.

🌍 Real-Life Example

Suppose a college wants to develop a simple Student Result Management System with fixed requirements.

First, requirements are collected, then design, coding, testing, deployment and maintenance are completed one after another.

This is a good example of using the Waterfall Model.
