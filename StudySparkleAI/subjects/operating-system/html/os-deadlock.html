Deadlock

1. What is Deadlock?

Deadlock is a situation in an Operating System where two or more processes are waiting for resources held by each other.

In simple words, processes keep waiting for each other and none of them can continue their execution.

Example:
Process P1 has Resource R1 and is waiting for R2.
Process P2 has Resource R2 and is waiting for R1.

Both processes keep waiting. This situation is called Deadlock.

2. Need to Study Deadlock

  • It can stop processes from executing.
  • It can waste system resources.
  • It can reduce system performance.
  • It can cause programs to stop responding.

3. Conditions for Deadlock

Deadlock occurs when the following four conditions exist at the same time:

  1. Mutual Exclusion
  2. Hold and Wait
  3. No Preemption
  4. Circular Wait

4. Mutual Exclusion

Mutual Exclusion means a resource can be used by only one process at a time.

Example: Only one process can use a particular printer at a time.

5. Hold and Wait

Hold and Wait means a process is holding one resource and waiting for another resource.

Example: P1 is holding R1 and waiting for R2.

6. No Preemption

No Preemption means a resource cannot be forcibly taken away from a process. The process must release the resource itself.

7. Circular Wait

Circular Wait means processes form a circular chain where each process is waiting for a resource held by another process.

Example:
P1 → waiting for R2
P2 → waiting for R3
P3 → waiting for R1

This forms a circular wait.

8. Deadlock Example

Process Holding Waiting For
P1 R1 R2
P2 R2 R1

P1 cannot continue until it gets R2, while P2 cannot continue until it gets R1. Therefore, both processes wait forever.

9. Methods for Handling Deadlock

An Operating System can handle deadlocks using the following methods:

  • Deadlock Prevention
  • Deadlock Avoidance
  • Deadlock Detection
  • Deadlock Recovery

10. Deadlock Prevention

Deadlock Prevention is a method in which the Operating System prevents at least one of the four necessary conditions of deadlock from occurring.

Example: The system can prevent a process from holding one resource while waiting for another.

11. Deadlock Avoidance

Deadlock Avoidance checks whether giving a resource to a process can lead to deadlock. The resource is given only when the system remains in a safe state.

The Banker's Algorithm is a common deadlock avoidance algorithm.

12. Deadlock Detection

In Deadlock Detection, the Operating System allows deadlock to occur and then checks whether a deadlock has happened.

If a deadlock is detected, the system takes steps to recover from it.

13. Deadlock Recovery

Deadlock Recovery means removing the deadlock after it has been detected.

Common recovery methods are:

  • Terminate one or more processes.
  • Take resources back from a process.
  • Restart affected processes when necessary.

14. Banker's Algorithm

Banker's Algorithm is a deadlock avoidance algorithm. It checks whether allocating resources will keep the system in a safe state.

If the system remains safe, the resource is allocated. Otherwise, the request is delayed.

15. Safe State

A system is in a safe state when there is at least one order in which all processes can complete their execution without causing deadlock.

16. Unsafe State

A system is in an unsafe state when the available resources may not be sufficient to allow all processes to complete safely.

An unsafe state does not always mean that deadlock has already occurred, but it means the system is at risk of deadlock.

17. Deadlock Prevention vs Avoidance

Prevention Avoidance
Prevents deadlock conditions. Checks resource allocation before giving resources.
Works by restricting resource usage. Works by maintaining a safe state.
Example: Breaking a deadlock condition. Example: Banker's Algorithm.

18. Advantages of Deadlock Handling

  • Prevents processes from waiting forever.
  • Improves system performance.
  • Uses resources efficiently.
  • Improves system reliability.

19. Real-Life Example

Imagine two people standing on a narrow road. Person A waits for Person B to move, while Person B waits for Person A to move. Neither can move forward. This is similar to deadlock in an Operating System.

20. Summary

Deadlock is a situation where processes wait for resources held by each other and cannot continue execution. The four necessary conditions are Mutual Exclusion, Hold and Wait, No Preemption and Circular Wait. Deadlock can be handled using Prevention, Avoidance, Detection and Recovery techniques.
