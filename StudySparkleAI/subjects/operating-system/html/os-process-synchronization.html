Process Synchronization

1. What is Process Synchronization?

Process Synchronization is a mechanism used by an Operating System to control the execution of multiple processes when they share common resources or data.

In simple words, it makes sure that multiple processes access shared data in a safe and proper order.

2. Need of Process Synchronization

  • It prevents data inconsistency.
  • It protects shared resources.
  • It prevents incorrect results.
  • It controls access to shared data.
  • It allows processes to work together safely.

3. Shared Resource

A shared resource is a resource that can be accessed by more than one process.

Examples:
Shared memory
File
Printer
Database

4. Critical Section

A Critical Section is the part of a program where a process accesses or modifies shared data or resources.

Only one process should execute its critical section at a time when the shared resource cannot safely be accessed concurrently.

Example: If two processes are updating the same bank account balance, the code that changes the balance is a critical section.

5. Critical Section Problem

The Critical Section Problem is the problem of designing a system so that multiple processes can safely access shared resources without causing errors.

A good solution should satisfy three conditions:

  • Mutual Exclusion
  • Progress
  • Bounded Waiting

6. Mutual Exclusion

Mutual Exclusion means only one process can execute its critical section at a time.

Example: If P1 is using a shared printer, P2 must wait until P1 finishes using it.

7. Progress

Progress means if no process is inside the critical section, a process that wants to enter should be allowed to enter without unnecessary delay.

8. Bounded Waiting

Bounded Waiting means a process should not wait forever to enter its critical section.

9. Race Condition

A Race Condition occurs when multiple processes access and modify shared data at the same time, and the final result depends on the order in which they execute.

Example:
Suppose a bank account has ₹1000.
Two processes try to update the same account at the same time. If synchronization is not used, the final balance may become incorrect.

10. Synchronization Tools

Operating Systems provide different tools to achieve process synchronization.

  • Mutex
  • Semaphore
  • Monitor
  • Locks

11. Mutex

Mutex stands for Mutual Exclusion. It is a locking mechanism that allows only one process or thread to access a shared resource at a time.

Simple Flow:

Lock → Access Resource → Release Lock

12. Semaphore

A Semaphore is a synchronization mechanism used to control access to shared resources.

It is generally associated with operations such as wait() and signal().

  • Binary Semaphore: Usually has values 0 and 1.
  • Counting Semaphore: Can have a range of non-negative values.

13. Monitor

A Monitor is a high-level synchronization mechanism that allows only one process or thread at a time to execute code inside the monitor.

It provides a structured way to protect shared data.

14. Locks

A Lock is used to prevent multiple processes or threads from accessing a shared resource at the same time.

Example: Before accessing shared data, a process acquires a lock. After completing the work, it releases the lock.

15. Producer-Consumer Problem

The Producer-Consumer Problem is a common synchronization problem.

The producer creates data and puts it into a shared buffer, while the consumer takes data from the buffer.

Example:
Producer → Buffer → Consumer

Synchronization is required so that the producer does not add data when the buffer is full and the consumer does not remove data when the buffer is empty.

16. Readers-Writers Problem

The Readers-Writers Problem occurs when multiple processes access a shared data source.

  • Multiple readers can read shared data at the same time.
  • A writer needs exclusive access while writing.
  • Synchronization is required to avoid incorrect data.

17. Dining Philosophers Problem

The Dining Philosophers Problem is a classical synchronization problem used to explain resource sharing among processes.

Philosophers need shared resources to eat, so proper synchronization is required to avoid problems such as deadlock and starvation.

18. Starvation

Starvation occurs when a process waits for a very long time because other processes continuously get the required resources.

Example: A low-priority process may keep waiting because higher-priority processes are continuously selected.

19. Deadlock and Synchronization

Incorrect use of synchronization mechanisms can sometimes lead to deadlock, where processes wait for resources held by each other.

Therefore, synchronization must be designed carefully.

20. Comparison of Synchronization Tools

Tool Purpose
Mutex Allows one process/thread to access a resource at a time
Semaphore Controls access to one or more shared resources
Monitor Provides structured synchronization for shared data
Lock Prevents simultaneous access to a shared resource

21. Advantages of Process Synchronization

  • Prevents race conditions.
  • Maintains data consistency.
  • Protects shared resources.
  • Improves reliability of programs.
  • Allows processes to cooperate safely.

22. Real-Life Example

Consider a single ATM machine. If two people try to use the same ATM at exactly the same time, problems can occur. The ATM allows one person to complete the transaction before the next person uses it. This is similar to synchronization in an Operating System.

23. Summary

Process Synchronization is used to safely manage multiple processes that share resources or data. It prevents race conditions and data inconsistency. Critical sections, mutexes, semaphores, monitors and locks are important concepts used for process synchronization.
